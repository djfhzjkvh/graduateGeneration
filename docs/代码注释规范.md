# 代码注释规范

## 目标

项目代码需要保留必要注释，便于毕业设计答辩、后续维护和模块交接。注释重点解释业务意图、关键规则和设计约束，不逐行翻译代码。

## 注释范围

建议添加注释的位置：

- 类级别：说明模块职责，例如客户服务、任务服务、AI 调用客户端。
- Controller 类级别：说明接口面向的小程序端或管理端，以及主要使用角色。
- Controller 方法级别：说明接口对应的页面动作、核心副作用和后续权限边界。
- 方法级别：说明对外接口、事务边界、重要业务动作。
- 关键逻辑前：说明状态流转、权限边界、默认值、规则计算。
- 配置类：说明配置生效范围和原因。
- SQL XML：说明复杂查询的用途和主要筛选条件。

不建议添加注释的位置：

- DTO、VO 中含义明确的普通字段。
- 简单 getter/setter、普通赋值。
- 与代码完全重复的描述，例如“设置状态为 DONE”。

## 示例

推荐：

```java
// 新增跟进时同时更新客户最近跟进时间、下次跟进时间和客户状态。
customer.setLatestFollowTime(LocalDateTime.now());
```

不推荐：

```java
// 给 customer 设置 latestFollowTime 字段。
customer.setLatestFollowTime(LocalDateTime.now());
```

## 后续约定

后续新增代码默认遵守本规范。业务规则、权限规则、AI Prompt 处理、热度评分、定时任务和状态流转必须写注释。
