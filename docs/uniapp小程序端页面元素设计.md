# uniapp 小程序端页面元素设计

## 1. 文档说明

本文档用于规划“客户购房意向跟进提醒系统”的 uniapp 小程序端页面元素和功能模块。小程序端主要面向销售顾问使用，核心目标是帮助顾问在移动端快速完成客户查看、客户跟进、任务提醒和个人信息管理。

与后台管理端不同，小程序端不应做成复杂的后台系统，而应更偏向移动 CRM 工作台，强调高频操作、信息聚合和快速录入。

## 2. 小程序端定位

小程序端主要服务对象：

- 销售顾问
- 销售经理，部分场景可使用

核心使用场景：

- 查看今日待跟进任务
- 快速查询客户
- 新增客户线索
- 查看客户详情
- 记录跟进过程
- 创建跟进任务
- 完成任务提醒
- 查看个人信息并退出登录

## 3. 底部 Tab 栏设计

小程序端建议使用 4 个底部 Tab：

```text
首页 / 客户 / 任务 / 我的
```

各 Tab 职责如下：

| Tab | 说明 |
| --- | --- |
| 首页 | 顾问工作台，展示今日重点事项和快捷入口 |
| 客户 | 客户列表、客户详情、新增和编辑客户 |
| 任务 | 今日任务、待处理任务、逾期任务和任务完成 |
| 我的 | 当前用户信息、个人功能入口和退出登录 |

## 4. 登录页面

### 4.1 页面目标

完成小程序端账号密码登录，并初始化当前用户信息。

### 4.2 对应接口

| 功能 | 请求方法 | 接口路径 |
| --- | --- | --- |
| 小程序端登录 | `POST` | `/api/app/auth/login` |
| 获取当前用户信息 | `GET` | `/api/app/auth/profile` |
| 退出登录 | `POST` | `/api/app/auth/logout` |

### 4.3 页面元素

- 系统名称
- 用户名输入框
- 密码输入框
- 登录按钮
- 登录错误提示
- 加载状态

### 4.4 建议展示文案

系统名称建议使用：

```text
置业跟进助手
```

或：

```text
客户购房意向跟进提醒系统
```

### 4.5 交互说明

- 用户点击登录后，按钮进入 loading 状态。
- 登录成功后保存 Token，并跳转首页。
- 登录失败时展示错误提示。
- Token 失效时自动跳转登录页。

## 5. 首页工作台

### 5.1 页面目标

首页用于展示销售顾问当天最需要关注的数据和任务，让顾问进入小程序后可以快速知道今天要做什么。

### 5.2 页面元素

#### 5.2.1 顶部用户信息区

展示内容：

- 顾问昵称
- 所属部门
- 当前日期
- 问候语
- 当前角色

示例：

```text
上午好，张顾问
华西销售一组
```

#### 5.2.2 今日数据卡片

建议使用 2 行 2 列卡片展示：

- 今日待跟进
- 逾期任务
- 高意向客户
- 今日新增客户

#### 5.2.3 待办提醒区

展示今日需要优先处理的任务。

任务卡片字段：

| 字段 | 说明 |
| --- | --- |
| 客户姓名 | 任务关联客户 |
| 任务标题 | 当前任务标题 |
| 任务时间 | 计划执行时间 |
| 优先级 | 低、中、高、紧急 |
| 任务状态 | 待处理、已完成、已逾期、已延期 |

建议操作：

- 查看客户
- 立即跟进
- 标记完成

#### 5.2.4 高意向客户区

展示最近需要重点跟进的高意向客户。

客户卡片字段：

| 字段 | 说明 |
| --- | --- |
| 客户姓名 | 客户名称 |
| 意向等级 | 高、中、低 |
| 热度分 | 客户热度评分 |
| 预算范围 | 客户预算 |
| 关注区域 | 意向区域 |
| 下次跟进时间 | 下一次计划跟进时间 |

#### 5.2.5 快捷操作区

建议放置 4 个快捷入口：

```text
新增客户
记录跟进
创建任务
客户搜索
```

### 5.3 交互说明

- 首页支持下拉刷新。
- 点击客户卡片进入客户详情。
- 点击任务卡片进入任务详情。
- 点击快捷操作进入对应页面。

### 6.3 新增/编辑客户页

#### 页面目标

用于新增客户线索或修改客户基础信息。

#### 对应接口

| 功能 | 请求方法 | 接口路径 |
| --- | --- | --- |
| 新增客户 | `POST` | `/api/app/customers` |
| 更新客户 | `PUT` | `/api/app/customers/{id}` |
| 删除客户 | `DELETE` | `/api/app/customers/{id}` |

#### 表单分组

移动端表单不宜过长，建议分为以下三组：

```text
基础信息
购房意向
跟进备注
```

#### 表单字段

| 字段 | 说明 |
| --- | --- |
| 客户姓名 | 必填 |
| 手机号 | 建议校验手机号格式 |
| 性别 | 男、女、未知 |
| 年龄 | 数字输入 |
| 来源 | 微信、电话、到访、转介绍、导入 |
| 客户状态 | 新客户、跟进中、已到访、已成交、已流失 |
| 意向等级 | 低、中、高 |
| 预算最小值 | 数字输入 |
| 预算最大值 | 数字输入 |
| 关注区域 | 文本输入或选择 |
| 户型需求 | 文本输入或选择 |
| 购房目的 | 自住、投资、改善等 |
| 备注 | 多行文本 |

#### 交互说明

- 保存按钮应有 loading 状态。
- 必填项未填写时需要提示。
- 保存成功后返回客户详情或客户列表。
- 删除客户必须二次确认。

## 15. 交互与体验建议

- 小程序端以高频操作为主，页面层级不宜太深。
- 客户详情页底部应固定操作栏，方便快速打电话、记录跟进和创建任务。
- 客户手机号建议脱敏展示，但打电话操作应可直接调用拨号能力。
- 列表页必须支持下拉刷新和上拉加载更多。
- 表单提交必须有 loading 状态，避免重复提交。
- 删除、退出登录等危险操作必须二次确认。
- 状态、优先级、意向等级应使用统一标签样式，降低识别成本。
- 时间字段应统一格式化，避免直接展示后端原始时间。
- 接口异常需要统一提示，并记录调试日志。

## 16. 总结

uniapp 小程序端第一版建议围绕以下核心功能开发：

```text
登录、首页、客户、跟进、任务、我的
```

其中底部 Tab 建议为：

```text
首页 / 客户 / 任务 / 我的
```

小程序端的重点不是复杂管理，而是让销售顾问可以在手机上快速完成每天的客户跟进工作。第一阶段只要完成客户列表、客户详情、新增客户、记录跟进、任务列表和完成任务，就已经具备较强的实际使用价值。
