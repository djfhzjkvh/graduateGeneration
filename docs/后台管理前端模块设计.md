# 后台管理前端模块设计

## 1. 文档说明

本文档用于规划“客户购房意向跟进提醒系统”的后台管理端前端模块。模块设计以当前后端接口、数据库表结构和 CRM 业务流程为基础，优先保证 MVP 阶段能够落地实现，再预留后续扩展能力。

当前系统后端主要包含以下业务域：

- 认证登录：`auth`
- 客户管理：`customer`
- 跟进记录：`follow`
- 任务提醒：`task`
- 系统管理：`system`

后台管理端主要面向管理员、销售经理等角色，用于查看客户全局数据、管理团队成员、跟踪任务执行情况，并为后续报表、AI、项目管理等能力提供入口。

## 2. 后台管理端整体菜单

建议后台管理端菜单结构如下：

```text
后台管理
├── 工作台
│   └── 数据概览
├── 客户中心
│   ├── 客户列表
│   └── 高意向客户
├── 跟进任务
│   ├── 任务列表
│   ├── 今日任务
│   └── 逾期任务
├── 组织管理
│   ├── 用户管理
│   ├── 角色管理
│   └── 部门管理
└── 系统
    ├── 个人信息
    └── 退出登录
```

## 3. MVP 阶段必做模块

### 3.1 登录认证模块

#### 模块目标

完成后台管理端登录、登录态维护、用户信息获取和退出登录能力。

#### 对应接口

| 功能       | 请求方法   | 接口路径                      |
| -------- | ------ | ------------------------- |
| 管理端登录    | `POST` | `/api/admin/auth/login`   |
| 获取当前用户信息 | `GET`  | `/api/admin/auth/profile` |
| 退出登录     | `POST` | `/api/admin/auth/logout`  |

#### 页面与功能

- 登录页面
- Token 本地存储
- 请求拦截器自动携带 Token
- 登录失效自动跳转登录页
- 当前用户信息初始化
- 退出登录
- 路由守卫
- 根据用户角色控制菜单显示

#### 前端注意事项

- 登录成功后保存 Token 和用户基础信息。
- 所有后台接口请求需要统一处理 `Authorization` 请求头。
- 接口返回未授权时，应清理本地登录状态并跳转登录页。

### 3.2 工作台模块

#### 模块目标

为管理员和销售经理提供后台首页，快速查看客户和任务概况。

#### 当前接口情况

当前后端暂未提供独立的数据看板接口。MVP 阶段可以先通过客户列表和任务列表接口做基础统计，后续建议新增专用 Dashboard 接口。

#### 建议展示数据

- 客户总数
- 今日新增客户数
- 高意向客户数
- 待处理任务数
- 今日任务数
- 逾期任务数
- 最近跟进客户
- 团队任务概览

#### 后续建议新增接口

```text
GET /api/admin/dashboard/summary
GET /api/admin/dashboard/customer-trend
GET /api/admin/dashboard/task-summary
```

| 年龄     | 客户年龄                |

| 客户状态   | 新客户、跟进中、已到访、已成交、已流失 |

| 预算范围   | 最低预算和最高预算           |
| 关注区域   | 客户关注的购房区域           |
| 户型需求   | 客户关注户型              |

## 4. 通用基础模块

### 4.1 布局模块

后台管理端建议采用典型管理系统布局：

- 左侧菜单栏
- 顶部用户信息栏
- 面包屑导航
- 内容区域
- 多级路由出口

### 4.2 请求模块

建议封装统一请求工具，负责：

- 基础地址配置
- 请求头 Token 注入
- 统一响应解析
- 错误提示
- 登录过期处理
- 请求日志记录，方便调试接口问题

### 4.3 权限模块

MVP 阶段可以先做前端菜单级权限：

- 管理员：可访问全部后台模块
- 经理：可访问工作台、客户中心、任务管理、部分组织数据
- 顾问：原则上更多使用移动端或业务端，不建议开放完整后台管理

后续可以接入 `sys_permission` 和 `sys_role_permission` 表，实现按钮级、接口级权限控制。

### 4.4 字典模块

客户状态、任务状态、意向等级、客户来源等字段建议统一维护成前端字典。

MVP 阶段可先写在前端常量中：

```text
客户状态：NEW、FOLLOWING、VISITED、DEAL、LOST
意向等级：LOW、MEDIUM、HIGH
任务状态：PENDING、DONE、OVERDUE、DELAYED
任务优先级：LOW、MEDIUM、HIGH、URGENT
```

后续可接入 `sys_dict` 表实现后台可配置。

## 6. 推荐开发优先级

### 第一阶段：后台基础可用

第一阶段目标是让后台管理端可以登录，并完成客户、任务和组织人员的基础管理。

```text
1. 登录认证
2. 后台布局
3. 工作台
4. 客户管理
5. 任务管理
6. 用户管理
7. 角色下拉
8. 部门树
```

### 第二阶段：CRM 业务增强

第二阶段目标是补齐客户跟进链路，让管理者能够看到客户从分配到跟进的完整过程。

```text
1. 客户详情
2. 跟进记录
3. 客户分配
4. 客户标签
5. 任务转派
6. 基础报表
```

### 第三阶段：高级能力扩展

第三阶段目标是增强系统运营能力和智能化能力。

```text
1. 楼盘管理
2. 竞品管理
3. AI 管理
4. 消息通知
5. 操作日志
6. 系统配置
7. 完整权限管理
```

## 7. 前端工程建议

### 7.1 推荐目录结构

```text
src
├── api
│   ├── auth.ts
│   ├── customer.ts
│   ├── task.ts
│   ├── user.ts
│   ├── role.ts
│   └── dept.ts
├── assets
├── components
├── constants
│   └── dictionary.ts
├── layouts
│   └── AdminLayout.vue
├── router
├── stores
├── utils
│   ├── request.ts
│   └── logger.ts
└── views
    ├── login
    ├── dashboard
    ├── customer
    ├── task
    └── system
```

### 7.2 日志建议

为了方便调试，前端应在关键步骤记录日志：

- 登录成功或失败
- Token 失效
- 接口请求异常
- 表单提交失败
- 分页查询参数
- 关键业务操作结果

生产环境日志应避免输出密码、Token、手机号等敏感信息。

### 7.3 交互建议

- 列表页统一使用“筛选区 + 表格 + 分页”的结构。
- 新增和编辑建议使用弹窗或抽屉，减少页面跳转。
- 客户详情、任务详情适合使用右侧抽屉。
- 删除操作必须二次确认。
- 状态字段使用标签样式展示。
- 时间字段统一格式化。
- 所有异步操作应有加载状态和错误提示。

## 8. 总结

当前项目后台管理端最核心的模块是：

```text
登录认证、工作台、客户管理、任务管理、用户管理、角色管理、部门管理
```

这些模块与当前后端接口匹配度最高，适合作为第一阶段开发范围。后续可以基于数据库中已设计的跟进记录、客户标签、客户分配、报表统计、楼盘管理、AI 管理和系统配置等表，逐步扩展为完整 CRM 后台管理系统。
